# 宜昌 · 江山之间

宜昌Online 的独立微缩城市站点。使用 React、Three.js 与 Vite，将宜昌中心城区的真实道路、水域与建筑轮廓，呈现为明亮的立体沙盘；地标采用风格化模型。

## 本地运行与构建

需要 Node.js（支持 Vite 6 的版本）和 npm，以及支持 WebGL 的浏览器。

```bash
npm ci
npm run dev
```

生产构建与本地预览：

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`，可部署到静态网站托管服务。运行使用仓库中的 `public/data/city.json`，无需地图服务密钥；启动网站不需要重新生成地理数据。

## 探索方式

- 左侧目录或地图标签可定位七处地标；介绍卡右上角可以切换上一处、下一处。
- “靠近看看”进入更近一级的构图，再次点击可回到地标全景。“观察视角”中提供地标近景和俯瞰，镇江阁、天然塔还提供从水面望向建筑的江岸视角。
- 日夜按钮同时切换界面、环境与局部照明。镇江阁和天然塔以檐下灯线、窗光突出建筑层次，桥面使用小型灯头。
- 图层面板可控制建筑、树木和地标名称，也可暂停江面动态。船只和岸边家具是装饰性场景，不代表实时船舶或实测设施。
- 顶部“保存画面”导出当前三维画面的 PNG，文件名包含地标与日夜状态；导出不包含界面面板和 HTML 地标标签。
- 手机宽度下，目录改为侧边抽屉，地标介绍使用底部面板；单指旋转，双指缩放与平移。

场景尊重系统的减少动态效果设置。暂停江面动态不影响主动缩放和镜头切换；用户手动操纵镜头会停止自动环绕。

## 场景内容与表现范围

### 自建建筑样板：首信财富中心 S01

在原站 V11 的最新源码上继续开发，七处城市地标及其既有配准参数保持不变。目录新增「建筑展台 → 首信财富中心」，搜索「首信」也可进入。模型没有可靠的 WGS84 锚点、绝对尺寸和真北方向，因此只在独立展台展示；不会创建虚假的地图点或替换猜选的背景楼。

网页资源由已备份的首信 S01 交接 GLB 派生，Blender 原生文件未修改。网页材质保留米白石材、青蓝玻璃、窗格分色和参考时期字牌，严格使用平面着色。三轴以同一倍率归一到 16 个**展台展示单位**，这些单位不代表米。完整背面与屋顶仍属未核准外观。

| 档位 | Bytes | 三角形 | 模型绘制网格 | 使用时机 |
| --- | ---: | ---: | ---: | --- |
| 轻量 | 987,872 | 74,072 | 18 | 初次打开、较远观察 |
| 完整细节 | 1,498,684 | 117,844 | 19 | 靠近、正立面或放大到足够屏幕尺寸时 |

完整细节保留原交接包的全部几何，绘制网格从 100 合并到 19；轻量仅去掉石材微细接缝和裙房次级细分格，保留主体、主立面幕墙分格、竖肋、冠架、字牌与所有窗。两档包围盒一致。首屏不请求 GLB 或 GLTFLoader；离开展台取消请求、释放两档资源。细节加载失败时保留轻量模型并允许重试。资料和资源统计见 `docs/models/shouxin-asset-report.json` 与 `public/models/shouxin-s01/OPTIMIZATION.txt`。

**比例策略：**原城市普通建筑维持已有 3.8 倍高度展示规则。本轮没有对城市比例作未经审查的全局修改。自建资产始终保持三轴等比；后续地图接入必须同时核准坐标基准、锚点、前向、占地及尺寸，再选择整栋统一展示倍率、处理相交背景楼。不能将 3.8 倍单独施加在自建资产的 Y 轴，也不能以“100 归一单位”推断真实 100 米。

最新仓库和 Space 恢复说明、候选/HOLD 边界以及九类之外的额外资产清单，记录在 `docs/models/asset-inventory-20261109.md`。其他资产本轮仅核查和登记，没有宣称接入或通过实景验收。

针对本轮风险的无 GPU 检查：

```bash
node scripts/check-shouxin-assets.mjs
node scripts/check-authored-models.mjs
node scripts/check-landmark-alignment.mjs
```

这些检查验证实际 GLTFLoader 解析、原始几何一致性、异步加载/超时/释放与现有地标配准；不替代真实 WebGL 画面或物理手机性能测试。

覆盖范围为 WGS84 `[111.225, 30.645, 111.355, 30.755]`，约 **12.44 × 12.25 公里**。中心为 `[111.29, 30.7]`；局部坐标向东为 x 正方向、向南为 z 正方向，每米对应 0.02 世界单位。

当前数据包含 **13,800 个建筑轮廓部件、2,950 条道路段、47 个水体多边形、100 个绿地多边形、7 个地标**。建筑经过范围裁切与面积优先的远景筛选；这些数量不是宜昌全市的完整资产统计。

真实来源数据用于确定街道、江岸、岛屿和建筑的空间布局。建筑高度包含来源标签、楼层换算、2020 年遥感估算及固定 12 米参考值；渲染可对高度作微缩视觉夸张。地标模型、山体、桥梁细节、树木位置与比例是风格化表现，本项目不属于实景测绘或精确复原成果。当前数据不含 DEM 网格，绿地来源仅覆盖部分城区。

### 地标位置与方位

配准参数及依据保存在 `scripts/landmark-alignments.json`，生成数据时由 `scripts/landmark_alignment.py` 应用并写入来源说明。模型局部 `+X` 的方位使用 `axisHeadingDeg`，以真北为 0°、顺时针增加；古建入口统一为局部 `+Z`。桥坝的有序端点优先确定长度、方向和中心，地理旋转只由模型工厂应用一次。

| 地标 | 配准规则 |
| --- | --- |
| 葛洲坝 | 取保留坝顶道路的西侧大江主体坝段，模型沿两端连线并落在中点；泄水侧朝下游。该微缩模型不代表整个多分支枢纽。 |
| 镇江阁 | 用有名称的源建筑轮廓确定轴向，以现址重建阁“面对东山，背靠长江”的文献确定正背面。保持原参考点，缩放占地以适应岸线。 |
| 天然塔 | 按“底层塔门面向大江”的地名资料及源岸线确定入口方向；塔门、门匾和台阶在模型内同轴。保持原参考点。 |
| 至喜大江桥 | 水上连续段的接岸点用于主跨塔位，再按 250∶838∶215 补出边跨；不把约 838 米主跨误当成整桥长度。 |
| 夷陵大桥 | 沿同名道路水上主桥段放置，保留三塔模型。 |
| 磨基山、西坝岛 | 保持已有区域参考点，装饰性公园模型不声称还原某座实物建筑的正面。 |

镇江阁方向依据见[三峡集团《三峡》2022年第10期，第111页](https://www.ctgne.com/sxjt/fileDir/resource/cms/article/1278180/1418219/2023032716492726407.pdf)，天然塔方向依据见[宜昌市民政局地名资料](https://mzj.yichang.gov.cn/content-63849-997288-1.html)。具体角度是由已有地图几何推得的展示配准值，不是实测方位。两处古建不再采用向陆侧平移避水的方式；近景按缩放后的真实模型包围盒取景。

修改模型、方位配置或桥梁落位后可运行针对性检查：

```bash
node scripts/check-landmark-alignment.mjs
```

## 复现地理数据

依赖 **Python 3.10+、Shapely 2.x**。输入取自原宜昌Online 项目导出，源提交为：

```text
38c01bf002511c01294feacd8aa85e54e6342724
```

需要取得该提交对应的原项目 checkout；本仓库不重复收录整套原始导出。脚本读取其中的：

- `dist/data/gis-yichang/roads.geojson`、`water.geojson` 和 `buildings/*.geojson`
- `dist/data/riverside-yichang/greenspace.geojson`
- `dist/pois.json`

```bash
python -m pip install "shapely>=2,<3"
python scripts/prepare-city-data.py --source /path/to/original-checkout
```

默认重新写入 `public/data/city.json` 与 `public/data/sources.txt`。也可用 `--output /path/to/review-output` 生成到独立目录进行核对。脚本保留来源、坐标说明、模型表现范围、桥型依据及当前七条游客文案；它不会生成随机建筑位置或随机建筑高度。
