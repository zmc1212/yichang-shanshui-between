# 自动导览节奏修复 — 2026-11-12

原站：sites-project://appgprj_6af0b8d6dbec81919ea6c30c51e88270

基线：V61，bbd10150fbc1b86395aee63644b03d35561bf4ad。用户反馈自动导航切换太慢，像卡死。

## 原因

原默认每站14秒，首次建筑模型加载又被合并进无上限的导览暂停条件；加载结束后继续原剩余停留。模型下载/解析与加载队列可能明显延长总等待。面板没有倒计时和本次停留进度。镜头本身的1.15秒过渡不是主要原因。

## 修改

- 默认每站5秒；面板可选择快览3秒、标准5秒、慢看8秒。调整间隔保留本站已用时间，不从头计时。
- 下一站名称、剩余秒数与本站进度读取同一个导航计时器。控件内部刷新数字，不驱动整个城市App按200ms刷新。
- 模型等待独立于用户暂停，单次访问最多增加3秒前台等待。就绪时立即继续原停留；超时显示“载入较慢”，继续倒计时。默认档模型一直未就绪时约8秒进入下一站。
- 暂停、隐藏页面和覆盖层会冻结停留及加载宽限；迟到的模型通知不能恢复用户暂停。重复加载状态不会重置宽限。
- 手动前后切站立即生效，原换站回调被取消。最后一站显示结束倒计时，结束后不循环。

## 验证

`node scripts/check-city-tour.mjs`：18组通过。保留原11组行为检查（旧计时测试显式使用14秒），新增7组检查实际5秒默认、计时读取、调速、永不完成加载的3秒宽限、重复通知、暂停/覆盖层及旧回调隔离。

浏览器临时验证页使用生产React组件、hook与控制器：普通站间隔实测5001/5000ms，持续加载时首站到第二站8003ms，快览连续换站3001ms；检查了暂停、调速选择及加载提示。390px时导览卡clientWidth与scrollWidth同为364px，距详情卡9px；701px带真实侧栏宽度时导览卡clientWidth与scrollWidth同为167px。临时页已删除，不随站点交付。

上述浏览器检查针对导览控件与真实时钟，不代表三维GPU画面的新验收。本轮未改变城市几何、模型资产、道路数据或取景过渡。
