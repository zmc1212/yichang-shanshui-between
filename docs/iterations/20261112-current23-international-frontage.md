# Current23 国际广场前场：从实际铺装外缘重新接出

## 范围

仅适配现有 current23/06 两档模型的前场辅助铺装，不修改 GLB、sourceBounds、位置、朝向或展示比例。不新增建筑入口，不声称现场测绘或无障碍路线。保留旧模型专用分支及严格身份守卫；旧版测试并不代替本版测试。

## 几何依据与修正

独立解码轻量及精细 GLB 均确认 Light stone paving 顶面为源坐标 `y=-0.09975645499281255`，在 `x=32.9..33.9` 的连续外缘为 `z=27.500717184972686`。这不是整体包围盒最大 Z，也不是旧模型的 passage 边。

旧版从 z≈23 起的坡及下穿铺装会与新版实心平台相交，因此**不再生成这部分**。新版从已验证外缘接出 1 源单位宽短坡，在 z=27.7 到达 y=-0.13；后续梯形铺装扩至 x=36.8、z=30.1，再连接原外侧转折、长坡及沿江大道同侧人行道。保留源模型已有铺装与装饰，不覆盖或改造它们。

短坡展示坡度约 15.2%，不是无障碍坡道。现有模型和道路的展示高度差保持不变。无现场证据的组团配准与尺度仍保持 HOLD。

## 验证

运行 `node scripts/check-current23-international-frontage.mjs`：

- 直接读取并核对 **current23/06** 轻/精资产完整 SHA256，不读取旧模型目录；
- 解码全部两档模型，从真实 mesh world matrix 提取源三角形；
- 测试既有平台顶面外缘内侧 1×0.05 源单位区域的完整覆盖及三点接边高度；
- 用原有冻结 sourceBounds、统一 scale、yaw 和真实地形高度构造同一变换；
- 检查实际 renderer 生成的 Float32 铺装三角形、覆盖面积、法线、共享边高度；
- 对源三角形做三维裁剪，包含投影面积为零的立面；实体铺装仅可在外缘浮点容差内接触，不能覆盖新铺装内部；装饰若有重叠必须严格位于辅铺上方；
- SHA、资源 URL 或冻结边界任一改变都会关闭专用几何例外。

本次 41 个铺装单元、82 个实际渲染三角形，两档均无内部相交。仅有外缘 Float32 接缝接触，未使用整栋障碍豁免。结果见 `docs/qa/current23-international-audit/frontage-validation.json`。

当前云端 WebGL 不可用，因此这是源模型和实际渲染缓冲的几何验证，不是浏览器 GPU 视觉验收。不覆盖 23 项中的待核位置/朝向。

## 旧回归限制

`check-street-appearance.mjs` 的历史入口高度常量、`check-street-details.mjs` 的旧九州冻结哈希尚未迁移到 current23，不可用它们证明新版资产验收；没有修改旧断言来隐藏差异。跨版本基线比对由集成阶段另行记录。

V62 原始基线中，street-appearance / street-details 均先因缺失国际前场站点失败；本次恢复该站点后才继续触及后面的历史冻结值。旧冻结值未改。`check-city-tour.mjs` 的当前版验收已更新为验证新 profile 恢复，同时对 SHA、资源 URL 与 sourceBounds 篡改保留 fail-closed 检查。

## 集成复核

以精确 V62 源码提交 `a4f30a179fcacedec899d6211426e95802caed30` 独立恢复基线，使用相同 current23 配准数据、平地测试输入对比：其余六处街面完整 JSON 与连接 links 均保持逐字节相同，本次仅恢复国际广场第七处前场。V62 基线的两个旧街面测试本身首先因只有六处而失败；本次恢复后才继续触及上述历史高度/哈希断言。
