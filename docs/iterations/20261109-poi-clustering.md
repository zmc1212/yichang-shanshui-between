# POI 标签聚合与附近地点选择

原站：[宜昌 · 江山之间](https://yichang-miniature-city.gaoronghai.chatgpt.site)。从V23、提交`15ca9d262526ad78962f8cd0fef15ba86ae0afc2`接续，保留前一阶段的目录、定位链接、手机介绍和按需渲染优化。

## 问题依据

旧标签布局在重叠时逐行上移，桌面最多170像素、手机最多38像素，仍放不下便设置为`visibility:hidden`。这会使相邻点位从地图文字层消失，用户无法知道还有哪些地点。

真实浏览器V23全景基线：主视口1616×793，30个点的屏幕坐标均落在视口内，实际仅16个标签可见。屏幕沿江区域有许多相邻或几乎同位的商务楼宇，单靠上移难以完整表达。

## 实现原则

- 聚合只处理屏幕标签；模型、原始经纬度、沙盘坐标及配准依据保持原样。
- 每个当前可视点恰好出现在一个独立标签或一个有明确数量的聚合中，禁止因文字碰撞静默丢弃。
- 当前选中且位于画面内的地点单独保留，其余标签为它让位。
- 气泡先打开成员列表，可直接选中任一地点；同坐标点也能访问。另提供“放大这组”，让标签随画面间距自然拆分。
- 地图继续呈现当前视野中的地点；目录筛选沿用既有目录语义。聚合列表保留模型可用、待恢复、待配准及导览参考点的区别。
- 列表保留城市背景，支持手机、键盘和关闭后焦点恢复；关闭标签图层时同时关闭聚合列表和标签交互。
- 相机事件更新标签位置，成员组合改变才更新组件；不为聚合增加持续动画循环或重建城市。

- 14组布局检查通过，包含空数据、共点、选中点优先、有限分组直径、工具栏/详情面板避让、反序确定性、小视口及空间耗尽时成员保全。
- 保存真实V23投影至`docs/qa/poi-clusters-20261109/observed-overview.json`；沿用原按钮测量尺寸时，30点排为8个入口，成员完整且矩形无重叠。这个数字是固定输入的算法检查，实际页面会随字体、窗口和镜头变化重新分组。
- 真实城市工厂及OrbitControls的无GPU检查通过：分组相机保持方向和选中状态、组内参考点入框、同位反复点击不持续加倍、长桥整段范围不干扰邻近点取景、短屏空间不足可恢复失败、暂停恢复和静止停帧。
- 集成构建通过。普通地点、模型文件、配准文件及23项目状态没有变更。

## 验证边界

- 手机检查为响应式视口，不是实体手机触控、帧率、内存或发热测试。
- 共点及反复分组放大的极端边界由代码/投影检查覆盖；真实页面验证了实际相邻楼宇的展开与拆分。
- 聚合数随镜头、视口和字体重新计算，不是固定的地理行政分组，也不代表坐标精度提高。
- 23项仍是商务楼宇项目数，含多塔组团；7个城市模型、1个独立候选、15项待恢复的资产状态不变。阶段候选及配准待核准标注保留。
