# 建筑默认取景与近景细节

## 基线与范围

原站“宜昌 · 江山之间”，从 V29 / `57a1513ba290dba628c98383c87a87fb074f9bee` 接续。保留原站身份与访问范围，保留 23 个商务项目、7 个城市地标、POI 分组、当前模型版本及地图配准资料。

用户反馈点击 POI 后和“靠近看看”都显得太远。本轮调整镜头与信息卡，不改变模型的位置、朝向、占地或三轴比例。

## 调整

- 自建楼宇使用源模型经统一比例缩放、旋转后的八个角点与实际标签锚点计算投影，避免世界轴包围盒再次投影带来的空白。
- 默认建筑视图按可用画面的约 72% 取景；近景按约 94% 取景。先预留标签、工具栏、侧边介绍卡和底部空间；宽组团以完整横向范围为约束，因此不会保证楼高占画面相同比例。
- 桌面左上说明卡仅在实际与主体相交时增加顶部留白。手机按说明卡和介绍卡的实测位置取景；极短窗口无足够区域时保持当前镜头，待卡片尺寸变化后重新取景。
- 手机选择已有模型的地点时先展示紧凑信息卡，保留名称、展开介绍和靠近查看。主动进入近景、正立面或顶部视图也收起长介绍。
- 近景按钮可返回建筑全貌。另有“连同沙盘看”入口继续查看城市范围。
- 手动缩放上限随当前模型尺寸调整，可继续放大幕墙或顶部局部，不再受统一 1.8 世界单位最小视野限制。
- 待恢复和待配准的导览点继续观察街区；相机调整不把导览点的计算范围当作正式楼体。
- 保留轻量模型常驻、近景细节按需加载，以及周边地形、道路和背景楼。

## 验证边界

`scripts/check-city-render-lifecycle.mjs` 使用实际 Three.js 相机、OrbitControls 与场景工厂，独立从源模型尺寸计算八角点。检查 7 个自建模型的桌面、手机展开/收起介绍、正立面与顶部取景，以及缩放、背景保留、模型变换不变和原有聚合/渲染生命周期回归。该检查替换 GPU renderer，不代表 WebGL 视觉验收。

位置链接的编解码与视角约束检查通过。浏览器视觉验证记录另存于对应 QA 目录；真实地图尺寸、朝向和实景验收状态沿用已有说明，本轮不作新的测量结论。

V30 发布后，已在连接的 Chrome 验证桌面首信默认/近景/正立面/顶部，手机首信紧凑介绍与近景切换、万达完整三塔组团及日夜切换。真实截图与限制详见 [浏览器验证记录](../qa/building-camera-20261109/README.md)。
