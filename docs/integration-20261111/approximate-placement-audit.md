# 16 项新增沙盘候选的落位边界

本轮基于 V59 的原导图 WGS84 参考点和 city.json 轮廓作静态审计，不包含新增现场测绘或影像方位判读。

## 可立即采用

- 原有 7 项登记保持。新增 16 项可以在原导图参考点附近显示完整候选，明确标为“原导图附近展示 · 方位/尺寸待核”。此为沙盘展示落点，不是确认楼心。
- 所有轴使用单一等比。绑定当轮实际 GLB 的包围盒；不要复用旧局部模型的 sourceBounds。
- 采用统一、显式展示方向时必须标示“朝向示意”。不能把最近多边形最长边自动解释为建筑正面。
- 第 17 项用原目录候选，不自动声明为时代中心主塔；第 22 项不据照片左右推定 A/B。第 21 项已有原标签/外观对应，但尺度、接地、时相未实测。
- 不同时放默认与互斥备选。需要切换时在同一项目下切换，不额外增加项目点位。

## 必须防止误删底图

现有 planAuthoredGround 会在没有 feature IDs 时按包围盒重叠删除白模。新增近似候选必须在进入该分支前检测 `registration.suppressBackgroundReplacement`，并直接跳过删除，而非传空数组后走 fallback。这样不把附近楼误认为同一目标。

若视觉上重叠，可用“候选建筑周边底图淡化/收起”的可逆显示选项，但必须说明这是展示处理，不是确认覆盖关系。不要把地图道路、水体或大面积邻楼抹去。

## 地图证据的具体局限

- 美联、兴发、丽景、鑫鼎、旭光等最近轮廓高度为默认 12m，不能据此确定实际楼高。
- 宜昌之星在参考点 118m 以内没有近邻轮廓，不应自动吸附到最近楼。
- 长江的最近轮廓约 10610㎡，可能是整体区域，不能简单按其尺度放大单塔。
- 共和最近三轮廓均为12m默认高度，不能推定双塔分区。
- 外滩和致远的点位位于高塔轮廓内，属于更好的候选，但仍缺正面方向独立判读。

JSON 附件保留邻近原 GIS ID、轮廓、距离和高度，方便后续人工核对；它们是候选证据，不是自动替换指令。
