- 导图名称一致，pano id 为 144543，`scenic_map=1`。
- `product.openmap.scenelist` 中首信场景 id 1649136 的 longitude / latitude 就是上述两个原值。
- 页面加载的 `hyglobal.min.js` 将该数组原样赋给场景地图数据；`open_map.min.js` 的 `scenic_draw_hot` 从中取经纬度直接创建 `AMap.Marker`，没有先作其他坐标转换。
- 同一脚本另一分支 `getScene_hot` → `hot_add` 也直接使用这些值，微信定位显式请求 GCJ-02。
- [高德官方 JS 1.4 基础类文档](https://lbs.amap.com/api/javascript-api/guide/abc/basetype)明确采用 GCJ-02。由实际数据链确认本导图的坐标语义，不能继续称为未知，也不能标为 WGS84。

## 3. 朝向与统一比例

原生研究与临江照片确认模型局部+Z为临江宽面。按源轮廓长边轴向131.50°排除180°翻转，将正面朝向221.50°（西南）。最近江面方向约226.84°，属于同一临江方向。Three.js的yaw为`180°−frontBearing`，约−0.724314弧度。该角度由地图几何与照片推得，不是现场真北测量。

源模型宽高深为40.86:97.94:28.13归一单位，不能把它直接解释为米。旧16单位高展台模型在底图上相当于约334×230米占地，不能平移入真实地块。

当前按完整模型包围盒、0.25米轮廓内边距，三轴使用同一标量约0.0165694世界单位/模型单位。结果占地约33.85×23.30米，显示高度约81.14米。**81.14米只是占地等比拟合后的显示值，不是宣称真实楼高。** 地图原高度标签为96米，但没有原标签的测绘证据，也没有塔楼/裙房语义；未为迎合这个值而单独拉高或横向拉伸。

模型形体、竖肋、幕墙分格、冠架、裙房、字牌和原始Blender、两档GLB保持不变。只改变运行时位置、绕Y旋转与统一标量。

## 4. 背景避让与城市比例

- 使用旋转后的模型实际占地与背景楼多边形相交检查，只移除对应的1744号背景记录，未清空周围街区。
- 树木预留同一模型占地，避免替换白模后树长进模型。
- 模型位置固定，未通过平移锚点躲避道路或江面。
- 120米内背景楼用来源高度倍率1.0；120–300米以smoothstep过渡回原3.8；300米外保留原微缩展示。装饰树采用同一局部因子统一缩放。此规则不随选择、镜头或LOD变化。
- 调整原因：附近两栋来源90米的楼，原3.8倍规则显示为342米，若保持该局部夸张会压倒等比落地模型。来源高度仍可能是标签、遥感或默认估计，不因此成为实测。
