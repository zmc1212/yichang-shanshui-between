## 真实浏览器验证

云端内部预览能加载页面，但该浏览器 WebGL 无法启动，**不能据此作三维视觉验证**。随后在用户已连接的 Chrome 中打开实际发布原站，成功创建 WebGL，并检查最终功能修订。

桌面采用浏览器默认 1920 像素宽窗口，沙盘 canvas 实测 1616 × 793。手机布局使用临时 **390 × 844** viewport；结束时恢复默认。此为响应式浏览器验证，**不是物理手机、移动 GPU 帧率或长时间内存压力验收**。

### 手机缺陷修正证据

V12 首次手机截图中，建筑标签与顶部待核准说明靠得过近；V13 增加取景顶部留白，并在介绍面板实际排版后重新取景。最终 DOM 实测：

- 页面宽 390，`documentElement.scrollWidth = 390`。
- 顶部说明框 bottom = 170。
- 选中标签框 top ≈ 193.44，bottom ≈ 235.44，和说明分开。
- 底部详情框 top ≈ 450.81，bottom = 798，width = 366。
- 舞台 `scrollTop = 0`，没有此前历史版本出现的焦点滚动。

## 资源开销与真实性边界

| 状态 | 实际画面 draw calls | 实际画面 triangles |
| --- | ---: | ---: |
| 首信轻量展台 | 23 | 74,112 |

此表包含展台/地面；资产本身为轻量 18 个绘制网格、74,072 三角，细节 19 个绘制网格、117,844 三角。完整细节从原 100 个渲染网格合并到 19，并逐三角核对位置与材质。轻量减少约 37.1% 三角，明确删减范围见 `shouxin-asset-report.json`。

真实浏览器观察：两档都渲染后 `renderer.info.memory.geometries = 151`；关闭展台后降为 114，其中 3 个展台底板几何保留供复用，两档模型的 37 个几何被释放。再次进入轻量为 132，再进入细节回到 151。纹理计数始终为 3（原城市使用的资源），首信资源未引入贴图。此为所观察的一次进出周期，不能推断长期稳定性或具体显存字节。

首次城市画面为 113 draw calls / 562,295 triangles；不同镜头的城市值随视锥裁切变化，不能和建筑展台当作同等场景帧率对比。此处没有虚构 FPS、加载秒数或手机发热结论。

## 可复现的离线检查

- `npm run build` 成功。主 JS 约 976.99 kB、gzip 274.11 kB；GLTFLoader 是按需拆分的独立 45.04 kB 模块。Vite 对主 chunk 超过项目 950 kB 阈值给出提示，构建未失败；本轮没有为消除提示而抬高阈值。
- `node scripts/check-shouxin-assets.mjs <原始网页GLB>`：实际 GLTFLoader 解析，源/派生 SHA、硬边、材质、包围盒与完整三角对照通过。
- `node scripts/check-authored-models.mjs`：9 组实际 GLB 加载生命周期检查通过，包括按需分级、快速切换、失败保留轻量、显式重试、迟到结果、释放和解析超时恢复。
- `node scripts/check-landmark-alignment.mjs`：原七处地标单次旋转/缩放、坝端点、固定古建锚点、入口方向、5,799 个占地采样、桥塔接岸及道路反转稳定性通过；滨江锚点偏移为 0。
- `git diff --check` 通过。

检查中修复了一个异步缺陷：在不可取消的 GLTF parse 阶段超时后，迟到模型会被销毁但状态原先停在 loading。修正为可重试 error，并有复现测试。
