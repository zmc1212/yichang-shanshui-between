## 实机发现后的收尾修正

### 九州雨棚与外侧前场的空隙

V41截图显示，严格避让整个模型AABB会在雨棚至外侧铺装之间留下草地。实际源模型包含前伸构件，导出说明又明确移除了展示性forecourt，因此其完整AABB不等于全部地面均被建筑占据。

V42先增加5片窄接驳带。现场截图仍留断口；进一步核查发现起点误用了入口镜头观察点（GLB坐标[-10.03,3,16.62]），该点在雨棚前方。两级GLB没有绿色地面材质；旧带21个竖向采样均无模型三角形，实际粗网格地面高程约1e-9，远低于铺装0.055。因此根因是连接端点偏离门斗，不能归因为地面遮挡，也不能仅凭“没有穿模”判定视觉连通。

连接位置来自原导出报告 `Entry_curved_vestibule_closed_frames`：GLB边界x[-14.73,-11.27]、z[9.06,10.83]；解码GLB进一步找到其石材门阶的最前Z=10.99956716、顶面Y=0.1801239127460832。使用既有归一化、比例、旋转和平移映射到城市，只修正这条窄带，外侧前场、道路侧连接、模型变换与镜头预设均保持。此门斗本身是PATTERN_INFERRED模型构件；这里确认的是现有模型中的位置，并非现场测绘。

V43以低于整个模型最低面为条件延长铺装，实际画面显示门阶与铺装仍有竖向接缝。最终起点改至原门阶前沿稍外的源坐标X=-13、Z=11.001，间隔约1.84毫米展示尺寸；铺装起点与原阶顶同高，世界Y约0.070648716，再平缓下降至原前场约0.055。这样保留门阶边缘并消除入口落差，不通过抬高整个前场解决。

最终带宽按现有展示比例约4.6米，仍为8片、16个三角面、1152字节，合并在原铺装网格中，不增加绘制调用。独立审查对两级实际GLB的整个新走廊进行低处三角面裁剪，结果均为零：新带在门阶前方，没有低处模型实体；高处雨棚完整保留。使用明确的门阶连接与已核查走廊约束，旧的“低于整个模型最低面”不再作为这段带的验收条件。

该接驳仅对自己的模型XZ包络使用经过源模型核查的入口走廊例外；原750个普通轮廓继续完整平面避让，其他楼体、保留源建筑、道路和水体不享有例外。片间及旧前场端连续；地形升起侵入铺装或保留楼体阻挡时整带拒绝生成。完整证据见 ../../iterations/street-frontages-20261110.json。当前city.json没有terrain栅格，验证使用与场景一致的回退丘陵，不把它称为GIS地形验证。

### 所有选中地标的实体轮廓保护

将辅助路名的轮廓避让从自建商务楼扩展到镇江阁等已有实体地标，使用既有模型计算得到的世界包围盒。普通business-poi参考点不生成虚构建筑范围。此项只改变DOM标签位置，不改变地标坐标、模型或相机。V42正式浏览器复查：镇江阁选中时只显示不覆盖阁楼的“西陵一路”，DOM冲突为0，53次绘制、638596三角面，原步道和栏杆完整。江面动态打开时场景active符合原有船只动画，不能误判为按需渲染失效。
